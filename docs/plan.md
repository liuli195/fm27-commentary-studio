# 项目方案

## 第一版

1. 输入下一场对阵资料，以及本次需要更新的解说场景。先支持手动提供资料，再验证能否在上场结束后自动读取下一场。
2. 用文字模型为高频场景按场写新句。普通比赛动作使用通用说法，对阵介绍只使用已核实的赛程和交锋资料。
3. 提前合成所选语言的语音并生成本场音频目录。首版使用中文。先在独立输出目录核对文件是否符合原插件读取要求。
4. 游戏接入后，沿用现有插件的事件判定、排队和播放。原插件及其音频由用户自行安装。本项目只发布自行编写的代码、文档和样例。

第一批覆盖高频场景，另准备少量进球、扳平和改判短句。无法确定下一场对手时先准备通用语音。球队、比赛日期或存档发生变化时重新核对本场语音。

## 语言扩展

生成时明确指定语言，分别配置写词规则、解说音色和姓名读法。新增语言时复用场景分类和播放规则。

## 环境

- Windows（视窗系统）及已安装的 Football Manager 27（足球经理 27）用于最后的游戏兼容验证。
- Python 3.12（编程环境）与 uv（项目环境和依赖管理工具）用于独立生成程序。
- Git（版本管理工具）与 GitHub CLI（代码托管平台命令行工具）用于版本管理和发布。
- 文字生成与语音合成均保留本地和在线选择。模型、音色和服务等到首个功能确定后再选。
- 只有需要开发游戏内读取组件时才考虑 C#（编程语言）、.NET（编译和运行环境）与 BepInEx（游戏插件加载器）。首个独立生成版本只需要 Python。

初始化环境可执行 `uv venv --python 3.12`。仓库初始化阶段没有第三方运行依赖。
